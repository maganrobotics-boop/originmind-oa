# 实验室 OA V2 增量升级基线

日期：2026-09-21
基线提交：`7f496c6a429b6a9c6ca43d97693893afbcff6608`

## 结论

本项目不是从零建设 OA。现有系统已经包含成员准入、飞书与 GitHub 登录、保密协议、审批与不可变修订、统一待办、AI 知识库、会议纪要、飞书提醒和归档等能力。V2 应当在这些边界上增量演进为四个一级工作区：

1. 聊天：实验室 AI、成员私聊、群聊和项目群统一入口。
2. 通讯录：部门树、成员、角色、在研方向和发起会话入口。
3. 管理台：多项目总览，并聚合现有任务、会议、审批、知识和风险。
4. 邮箱：使用独立部署的开源 Webmail；OA 只负责入口、身份关联和业务引用。

现有审批、知识、会议和成员审核不会被删除，而是归入四个一级工作区中的业务子模块。

## 已确认的仓库现状

| 目标能力 | 当前实现 | V2 缺口 |
| --- | --- | --- |
| 聊天 | `direct_messages` 两人私聊；AI 助手已有独立会话界面 | 群聊、会话成员、已读游标、项目群、统一聊天首页 |
| 通讯录 | `members`、个人资料和成员列表 | 真实部门树、成员归属、部门负责人和按组织筛选 |
| 管理台 | 单项目任务、会议行动项、审批与知识库 | 项目实体、项目成员、多项目总览、跨模块项目关联 |
| 邮箱 | 只有账户邮箱字段，没有 Webmail | 独立 Webmail 服务、入口、登录衔接和邮件业务引用 |
| 会议 | 飞书会议机器人、事件读取和纪要生成 | 不需要嵌入飞书音视频页面；应继续使用跳转/机器人/纪要模式 |

当前 `app/page.tsx` 同时承担主壳、登录、审批、成员、聊天和大量状态管理，约 2,500 行。新增四大模块前应逐步拆分外壳和功能页面，但不能一次性重写认证与审批逻辑。

## 固定架构决策

### 继续使用现有技术栈

- OA 主应用继续使用 Next/Vinext、Cloudflare Workers 和 D1。
- `members`、`auth_identities` 和现有会话仍是身份与准入的唯一事实来源。
- NDA、管理员/项目负责人权限、限流、同源校验和迁移冻结机制必须复用。
- 不引入另一套 PostgreSQL、Redis 或新的用户中心。

### 聊天分两步演进

第一步先在 D1 上建立通用会话模型，替换“只按双方邮箱查询”的限制。实验室规模下可继续短轮询，以较小风险交付群聊和项目群。

第二步在确实需要在线状态、输入中提示和即时推送时，引入 Durable Objects。每个会话对应一个对象，WebSocket 只承担在线协调和广播；成员资格、项目关系和审计索引仍落 D1。不得使用一个全局对象承载全部聊天室。

推荐表：

- `conversations`：`direct | group | project | ai`
- `conversation_members`：成员、角色、加入/退出时间、已读游标
- `conversation_messages`：发送者快照、正文、回复关系、编辑/撤回状态
- `conversation_attachments`：R2 对象与安全元数据
- `conversation_events`：改名、入群、退群等审计事件

现有 `direct_messages` 保持只读兼容，采用确定性一对一会话键迁移，确认数量和哈希后再切换写入路径。

### 项目从字符串升级为实体

当前项目名由 `OA_PROJECT` 常量固定。V2 新增：

- `projects`
- `project_members`
- `project_links`，将审批、知识条目、会议、工作项、会话和邮件引用关联到项目

现有联合研发项目作为第一个项目回填。`project_work_items` 增加 `project_id`，旧 `project` 文本在兼容期保留。审批修订和既有审计记录不做破坏性改写。

### 通讯录复用成员，不建立第二套人员表

新增 `departments` 和 `department_memberships`。从现有个人资料中的部门字符串生成初始部门，并由管理员核对；兼容期继续读取原字段。部门层级采用 `parent_id`，成员可有一个主部门和多个协作部门。

### 邮箱是独立服务

Roundcube 适合作为第一版 Webmail 客户端，但它是 PHP 应用，不能运行在当前 Workers 代码中。建议部署到单独的容器/虚拟机，使用 `mail.omindos.ai`，OA 提供同品牌入口或顶层跳转，不用 iframe。这样不会受到当前 `frame-ancestors 'none'` 与摄像头/麦克风策略影响，也能独立更新安全补丁。

OA 只保存用户明确关联到项目的邮件元数据，例如 message-id、主题、发件人、时间和 Webmail 深链；默认不复制整箱邮件、不保存邮箱密码、不让 AI 自动读取全邮箱。邮件账户和单点登录方案取决于现有邮件服务商，必须在部署阶段单独确认。

## 数据迁移原则

1. 全部迁移只新增表、列和索引；生产切换前不删除旧对象。
2. 新表使用当前 `members.id` 作为成员引用，邮箱仅作显示快照或兼容查询。
3. 对旧私聊和单项目数据先回填、核对计数与哈希，再切换 API。
4. 现有审批修订、NDA 证据、归档哈希和迁移账本不可重写。
5. 新增迁移必须进入现有受保护发布链，并更新精确哈希与测试，不通过手工远端 SQL 绕过。

## 实施顺序

### 批次 0：工程基线

- 固化本决策文档。
- 将手写 Worker `Env`/`ExecutionContext` 与实际绑定对齐，后续改为从部署配置生成类型。
- 建立 V2 迁移、API、权限和浏览器测试清单。

### 批次 1：四区导航与通讯录

- 主导航收敛为聊天、通讯录、管理台、邮箱。
- 原审批、待办、知识、成员审核通过二级导航保留。
- 引入部门树和成员筛选；可从成员卡片发起私聊。

### 批次 2：通用会话与群聊

- 建立通用会话表和服务端权限检查。
- 迁移现有私聊，提供群聊创建、成员管理、消息列表、发送和已读游标。
- 建立项目群，但项目移除成员时同步撤销访问。
- 先保留轮询作为回退路径；实时连接单独启用。

### 批次 3：多项目管理台

- 建立项目与项目成员实体。
- 将现有单项目工作项回填到默认项目。
- 管理台聚合里程碑、风险、行动项、审批、知识、会议和项目群。

### 批次 4：邮箱

- 部署 Roundcube 和 HTTPS 域名。
- 接入现有 IMAP/SMTP 服务；若实验室尚无邮件服务器，邮件服务器选型另立项目，不能与 Webmail 客户端混为一谈。
- OA 增加入口和“关联到项目”动作；完成权限、退出和审计验收。

### 批次 5：实时与增强

- 以会话 ID 分片 Durable Objects，启用 WebSocket Hibernation。
- 增加输入中、在线状态、即时已读回执和断线恢复。
- 附件进入 R2，保留大小、类型、恶意内容和访问权限检查。

## 第一阶段验收标准

- 登录、准入、NDA、审批和知识库回归测试保持通过。
- 一级导航明确出现四个工作区，原能力都有可发现入口。
- 管理员能建立部门；成员能按部门查找并发起私聊。
- 能建立群聊、添加/移除成员、发送消息；非成员无法读取历史或猜测会话 ID。
- 默认项目完整保留当前工作项和会议行动项。
- 邮箱入口在服务尚未配置时明确显示“待配置”，不能伪装为可用。
