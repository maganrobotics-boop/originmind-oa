# OA 管理员查看成员会议纪要

基线：main `335eae843cf242ea2af7ddec7c5488ada9c6bf47`（PR #92）。

## 本次交付

聊天工具栏“已保存文档”旁，已完成准入的管理员看到“成员会议纪要”，进入 `/admin/meeting-minutes`。页面读取独立的只读管理员 API `/api/admin/meeting-minutes`。列表显示提交人、提交时间、任务状态；可查看提交文字、处理要求和生成成果，可下载提交文字、已校验的 Markdown/Word 成果。

“实时”采用页面可见时每 5 秒轮询；请求不重叠，后台暂停，回到前台立即刷新。每页最多 50 条，使用提交时间+ID 游标翻页；历史页明确提示返回最新上传。网络错误保留旧列表并标记过期，不显示虚假的“暂无记录”；权限失效清除列表/详情、停止当前订阅。

## 明确边界

- 接入的是 `origin=oa`、`kind=meeting_minutes` 的已持久化任务。排队/处理中就可查看，不以成果生成或 OA 归档审批通过为条件。
- “选择文件”不等于“已经上传到任务库”。当前 TXT/MD 等材料在发送处理要求前可以只在浏览器中，因此管理员不能看到尚未发送的本地附件。成员导入后选择“会议纪要”提示并发送，才产生这里可见的任务。
- 不根据任意文件名、正文关键词猜测会议类型，不扩大普通文档、问答、私聊或其他来源的访问权限。原始资料直接归档形成的知识投稿仍在既有审批页面查看，不伪装为本列表已覆盖。
- 管理员预览的是任务收到的文字，不代表源 PDF、图片、DOCX 二进制已保留。下载“提交文字”明确使用 TXT；Word/Markdown 成果仅返回已有且通过摘要校验的保存字节。
- 新接口只导出 GET，不可运行/重试/取消他人任务、修改记录、自动归档或绕过入库审核。原有成员接口保持本人范围，原生命周期和清理策略不变。不增加数据库迁移、模型调用或外部服务。
- 每个读取查询重用当前成员身份、账号绑定、mutation revision、active 状态、已归档且签署主体/版本匹配的 NDA 守卫。管理员身份只由服务端现有授权解析。所有响应禁用缓存，正文按纯文本渲染。
