# 人员工作台

入口 `/people-workbench`，兼容入口 `/expenses`。主页包括工作与成果、消费与报销、绩效与报酬。OA 侧栏增加入口，原申请支持 `/?approval=<id>` 直接打开。通讯录中的成员姓名与“个人主页”按钮可打开对应主页，“我的个人主页”使用 `?person=me` 打开登录者本人。普通成员只能进入自己的业务主页，管理范围仍由后端权限决定。

## 数据与权限

先执行 `migrations/expense-ledger-20261007.sql`，再在私有运行数据库配置账单姓名与成员关系、唯一工作审核人和异议处理人。不要把账单、成员身份、真实付款资料或运行数据库提交到仓库。尚未核实的账单姓名保持未关联。

支付宝 CSV 按配置姓名匹配亲情卡、代付及对应退款；保留来源字段和原文件行号。交易号去重，同号金额或归属冲突拒绝覆盖。以整数分计算金额，退款匹配原付款并且只扣一次。新增消费均待本人确认；管理员不能代替本人确认。账号关联或退款导致净额变化时，原确认失效。

普通成员仅能读取本人主页。管理员和经费负责人可查看管理范围、导入和关联账号。确认后才能登记报销进度，实际到账必须提供日期和依据，不能超过本笔净支出。预计全部报完日期在尚未完成的每一笔都填写日期后才显示。

周报来源包括本人提交的 OA 资料库周报、本人已完成的 AI 周报草稿，以及主动导入的原文。原文保留为快照，本人可以修改工作说明后确认提交。提交通过既有“流转审批”交给配置的单一审核人；重试复用创建键。只有已归档且具有该审核人的真实审批记录，才显示审核通过。退回记录从原 OA 申请修改重提。汇总周报不会按名字自动猜测个人贡献。

消费和未提交工作记录的异议进入配置处理人的待办。待办详情只对当事人、指定处理人及管理权限开放。原项目待办仅显示受限的入口，不通过通用任务接口结案。处理人填写意见后，记录回到本人重新确认；处理人不能直接将其标记为本人认可。每次操作保留审计。学生的消费确认、周报确认与未完成报销由原记录动态生成“待处理”任务；完成原记录后自动更新，不通过通用任务勾选代替确认。异议处理中暂不占用本人确认待办，处理后再回到本人。

绩效报酬读取现有技术成果和劳务报酬申请，未申报或未核定的金额保持未知。终审金额、实际已发与未发金额分开显示。登记实际付款不会发起转账。

## 运行与验证

- `node --test tests/expense-ledger.test.mjs`：去重、退款、隐私范围、本人确认、撤销权限、异议分派/处理/再确认、周报不可代确认、提交重试和到账依据、本人待办范围及确认/异议/报销状态衔接。
- `npm run typecheck`；对新增页面与模块执行 ESLint。
- `PEOPLE_BROWSER_EXECUTABLE=<chromium> node scripts/check-people-workbench-browser.mjs`：仅使用合成数据检查 1280/390/320 像素视图、账单原记录、弹窗错误、周报修改和空报酬状态。

发布时从正在运行的实际版本创建候选，按精确位置接入侧栏、申请深链、项目待办入口和隐私过滤；不能用较旧分支覆盖线上项目工作台或里程碑功能。使用数据库副本验证后备份生产 SQLite，执行增量建表与私有导入，再切换发布目录。回滚仅切回代码目录，新增表和导入记录保留，不回滚整个数据库以覆盖他人的同期写入。

人员问答已接入 OA 助研；支持实名、已绑定账单别名和明确指向上一位成员的追问。按当前访问权限即时汇总工作、消费报销、贡献与报酬，返回个人主页入口。没有依据的用途、绩效、工资和到账记录保持待补充；汇总不进入公开知识库。较新的私聊机器人部署由 scripts/patch-personnel-integrations.py 接入同一查询。

历史消费允许本人批量填“已报销”或“报销中”，同时确认归属，保留操作审计。本人填报的已报销状态与实际到账凭证金额分别记录，财务继续核对；已核验到账、全额退款或无需报销的记录保留原结论。管理员和财务不能代替本人执行填报确认。重复账单按交易号核对并去重，保留已有报销状态。

财务使用同一人员台账，可查看采购审核和劳务报酬详情、原始账单以及成员填报状态；待处理中提供财务台账核对入口。列表在切回窗口及每 30 秒同步一次，编辑中保留输入。服务端 OA_FINANCE_IDENTITIES_JSON 可配置经核实的 OAuth 财务身份，每项必须提供 email、accountUserId、displayName，且主体与邮箱严格绑定。部署账号配置、实际账单和人员映射不得进入公开仓库。财务可见性不改变原申请指定审核人、本人确认和异议处理人规则。
