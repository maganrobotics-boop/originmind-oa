# Newbie Village browser regression contract

The old browser journey required the welcome/login screen, an email verification
code, and manual agreement approval. The page now starts in local guest mode,
uses account/password login, and permits formal records after automatic OA
archival. Waiting for the retired welcome screen caused the same false baseline
failure in PRs #116 and #119.

`chat-cloudflare/scripts/check-newbie-village-browser.mjs` now exercises the real
Chat `handleRequest` and migrated in-memory SQLite database. The external OA
archive is a bounded test double, with both failure and successful archive
responses. All identities are synthetic. A loopback-only session bridge carries
the actual login-generated tokens without changing production Secure cookies.
No production account, OA archive, email service, model, or deployment is used.

## Coverage

The desktop (1280×900) and mobile (390×844) journeys assert:

- All seven courses and materials are browsable without login/agreement or writes.
- Local profile, completion and evidence survive reload; formal submission opens
  the optional login dialog; closing it preserves public access.
- Account/password login loads the real dashboard. Unsigned accounts still browse
  courses, while formal submission and sync request the real-name agreement.
- Archive failure leaves the agreement unsigned and preserves local records.
  Successful archival immediately stores `approved`, an automatic OA reviewer,
  the exact name, version, content hash and acceptance time. No manual review runs.
- Formal submission enforces prerequisites. Sync preserves exact evidence, walks
  sequential unlocks, retries after partial failure, and skips locked/completed
  records or records that already have server evidence. Local data is retained.
- Formal profile/task updates survive reload. A failed write cannot appear as
  completion or silently become a local save. Logout restores local-only records.
- Both viewport widths and unhandled browser errors remain checked.

The administrator journey reads the same records generated by those signings:
no pending approval, correct approved/all filters and refresh, exact archive
metadata, no review buttons or mutations, and access denied after session expiry.
The old administration page still contains legacy review wording/controls for
historical pending records; this test does not claim that the whole admin UI or
review endpoint has been removed.

No timeout has been increased, no assertion is skipped, and the original Chat
workflow still executes this script. `Check Newbie Village Contract` additionally
runs it on branch pushes and pull requests so a conflicting Draft PR can receive
an exact-head result independently of mergeability and unrelated Chat checks.
Screenshots and a payload-free request/check report are retained as CI artifacts.

## Local command

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
BROWSER_REPORT_DIR=/tmp/newbie-contract \
node chat-cloudflare/scripts/check-newbie-village-browser.mjs
```

`PLAYWRIGHT_EXECUTABLE_PATH` and `PLAYWRIGHT_ARGS_JSON` optionally select an
installed local Chromium. CI uses the pinned Playwright browser. Passing this
specialty check does not imply that every Chat/OA test passes, or that #116/#119
have had their unrelated merge conflicts resolved.
