# 飞书用户身份旁听：OA 首版接入

基线：main `8a4a4dceef5e68f46830154695f903645fde6107`。

## 依据与实现边界

依据用户提供《飞书智能体入会旁听 - 飞书 CLI - 开发文档 - 飞书开放平台》PDF，文档标注更新 2026-07-03，第 1–7 页。具体接入使用其第 5 页列出的 HTTP API，而非在 Cloudflare Worker 里启动 CLI 进程。

原文规定：以用户身份旁听；本人必须在会，会议所有者须启用“允许智能体入会”；字幕、会中聊天、参会人进出通过轮询读取。没有独立机器人出现在参会列表，也不能在会议中发声。需要灰度资格、用户身份权限 `vc:meeting.meetingevent:read`；PDF 给出的客户端最低版本为 7.68，CLI 路线最低版本为 1.0.55。本 HTTP 实现不要求终端安装 CLI。

补充核对官方 `larksuite/cli` 源码（读取时 main 为 `32d198896816e9416711468c20b14df3dbbc63f3`）：`shortcuts/vc/vc_meeting_list_active.go` 与 `shortcuts/vc/vc_meeting_events.go`。确认原生响应是 `data.meetings`、`data.events`、`has_more`、`page_token`；并非 CLI 整理后的顶层 JSON，也不应误用 `items`。分页大小 100，真实 `meeting_id` 为长整数字符串，不是九位会议号。

## 交付的操作链路

OA 现有聊天中增加“会议模式 · 飞书旁听”入口；`@会议模式` 命令优先交给此入口，不发往知识问答模型。原四项功能、真人聊天、文档预览与审批保持不变。

1. 单独授权会议读取：复用现有应用配置，但不改变 OA 登录范围。Authorization Code + PKCE，五分钟加密 state cookie；回调再次校验当前 OA 准入、账号、成员修订和租户。
2. 查询本人正在参加的会议。多个会议必须选择；只使用 API 返回的长 ID，不把邀请链接中的九位会议号传入事件接口。
3. 明确确认已告知参会人、获得内部整理许可后开始。服务端签发本次监听 ID；每轮先核对本人仍在对应会议，再取一页事件。前台约每五秒轮询，有更多分页则连续补拉；权限失败、异常分页或网络错误暂停，不伪装成功。
4. 字幕按句子及说话人标识去重和修正，兼容声纹 100/101/102；文本聊天、进出事件保留；非文本和未知事件明确标注，绝不自动读取共享链接或原始音视频。
5. 手动结束，或查询确认本人已不在会议后，为已采集片段创建 `meeting_minutes` 任务；材料分段，不截断。复用现有任务生成、版本校验、Word/Markdown、文档卡片、编辑和“提交 OA”。本人和管理员按原权限可读任务，未经审批不入知识库，不向公共 Chat 发布。

## 刻意限定为前台旁听，不是无人值守参会服务

本版不新增数据库表、不新增定时 Worker、不新增 webhook、不改发布门禁。必须保持 OA 页面打开。手机后台、锁屏、网络中断可能暂停/延迟轮询；刷新或清空聊天会释放尚未持久化的原文。页面提供离开提醒和原文导出，且显示最后成功拉取时间。尚未创建任务的原文仅在页面内存；已创建任务及其材料沿用 OA 原任务存储和生命周期。

不能宣称正在当前真实会议旁听、后台 24 小时采集、全会无遗漏、读取到幻灯片/共享文档，或已在生产启用。空字幕不会生成虚构纪要。分页安全上限 200 页/轮，采集内存预算 1,000,000 个估算字符和 20,000 条记录，达到上限暂停，原内容保留；不会静默删除旧记录。

## 凭证与访问边界

所有入口先验证当前 OA 登录、实名、保密协议，再以现有 `taskActorGuard` 直接查询成员修订和有效 NDA，避免仅依赖旧登录缓存。外部令牌不能由客户端提交。

UAT 仅由服务器请求飞书换取，存入 AES-GCM 加密、Secure、HttpOnly、SameSite=Strict 的短期 cookie；关联 OA 成员/账号/修订、应用、租户与 OA origin。前端 JavaScript不能取得明文 UAT。授权临时 cookie 为 SameSite=Lax，包含 PKCE verifier 和随机 state，五分钟失效，回调清除。凭证不写日志、不写仓库、不写 localStorage。使用固定的飞书 API 地址，拒绝跳转，限制响应体为 1 MiB。

本版没有服务器持久化令牌库，也没有 refresh token；授权最多保留两小时且受飞书较短有效期限制，到期须重新授权。重新授权会跳转页面，因此有原文时先导出，或另开 OA 页面授权。断开功能清除此浏览器旁听凭证，并非撤销飞书平台全部应用权限。多标签页共用短期 cookie，第二标签页开始新会议后，第一标签页的旧监听 ID 被拒绝，不自动切换会议。

## 上线前必需的操作（本次未执行）

- 飞书应用：申请并发布用户身份权限 `vc:meeting.meetingevent:read`。依 PDF，数据范围为“按条件筛选 → 会议的归属者 → 包含 → 与应用可用范围一致”。确认本人的灰度资格，以及每场会议所有者开启“允许智能体入会”。
- 飞书回调白名单新增 `<OA_PUBLIC_ORIGIN>/api/lab-ai/meeting-listen`；原登录回调保持不变。
- 在正确的 OA Worker 安全配置独立的 `OA_MEETING_TOKEN_KEY`：随机 32 字节转成 64 位十六进制字符串。不要使用测试文件中的合成密钥，不要把真实密钥发到聊天或提交 GitHub。
- 设置 `OA_MEETING_LISTEN_ENABLED=true`。为避免生成式部署配置覆盖普通变量，可将此开关作为 Worker Secret 配置；不向仓库提交生产值。依赖现有 `FEISHU_LOGIN_ENABLED`、`FEISHU_LOGIN_APP_ID`、`FEISHU_LOGIN_APP_SECRET`、`FEISHU_LOGIN_TENANT_KEY`、`OA_PUBLIC_ORIGIN`。缺配置默认关闭。
- 纪要生成继续需要现有 `OA_AI_TASKS_ENABLED` 与模型任务服务。此 PR 不自行启用、迁移、修改配额、扩大可见性或调用生产模型。
- 完整 CI 通过后，按原生产审批流程授权部署；随后用户在 OA 中亲自完成授权和实际入会测试。
