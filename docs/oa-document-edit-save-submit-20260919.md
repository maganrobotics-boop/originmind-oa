# OA 文档：编辑、保存草稿、提交审批

适用范围：OA 聊天中的会议纪要、资料整理和项目总结等已完成的文档任务。公开 Chat 不修改。

## 用户流程

文档卡片和文档预览均提供“编辑 / 保存草稿 / 提交 OA”。编辑可修改标题与正文；保存会同步重建 Word 和 Markdown。保存草稿不提交审批、不生成知识条目、不会调用模型；可从“已保存文档”重新打开。存在未保存修改时使用“保存并提交”，只有保存确认成功后才提交对应版本。提交仍需用户核对和确认，审批通过后才进入知识检索。

## 数据和权限

沿用原任务、成果文件和保留期限表，无新增迁移。`temporary` 且 `expires_at IS NULL` 表示主动保存的草稿，API 显示 `draft`；既有清理查询要求到期时间不为空，因此不会误删。已有临时成果仍按原七天规则处理，历史成果不追溯清理。

保存要求当前成员、账号、成员版本和保密协议有效；只能修改本人已完成且未开始送审的任务。保持现有管理员只读查看会议纪要的权限，不扩大其他任务的访问范围。

正文和两个文件在同一 D1 事务内更新；乐观版本校验阻止旧窗口覆盖新稿。归档先对同一任务版本加保护，再使用原审批入口。进入 archiving 或 submitted 后禁止覆盖内容。网络响应丢失时应先核对状态，不能将未知状态显示为成功。

## 验证

新增 `tests/oa-document-draft.test.mjs`：真实 SQLite + 实际草稿存储/API/文件生成模块，覆盖版本冲突、丢失确认重试、事务回滚、归档竞争、权限变化、草稿保留和文件下载。鉴权会话/平台环境为合成夹具，不代表生产真人登录验收。

上线前须通过 CI 并完成登录态人工验收：生成纪要→编辑标题正文→保存→刷新重新打开→下载核对→再次编辑→保存并提交→管理员审批核对。代码提交不代表已经合并或发布。保持现有生产人工发布流程。
