# OA AI 工作台 / 飞书任务入口（第一版）

## 已实现范围

OA 的 AI 助手页面增加“AI 工作台”入口，地址 `/ai-workbench`。
支持文档整理、项目周报、会议纪要、项目方案。用户填写任务要求并粘贴文字，
或读取本地 UTF-8 TXT / Markdown 文件。任务和 Markdown 成果保存在本人私有任务记录中，
可以重新打开、预览、下载 Markdown，或者按需导出真正的可编辑 `.docx`。
Word 导出包括标题、正文、加粗、简单列表和表格；不是把 HTML 改成 `.docx` 后缀。

飞书第一版只接收已绑定 OA 成员的机器人私聊：

```
任务：将以下材料整理为项目周报
材料：本周完成……
```

或先转发一条文字消息，再**回复那条消息** `/任务 整理为周报`。
收到普通文字只暂存，不自动执行。暂存源材料保留24小时、每人最多50条。
合并转发、图片、附件和云文档链接不直接读取；未读取的材料会明确失败，不能声称“已解析”。
单独粘贴一个链接只视为文字，系统不访问链接中的正文。
结果正文会通过机器人私聊回传，Word / Markdown 文件通过本人 OA 登录后下载。
目前不自动上传 Word 附件到飞书，不抓取任何会话历史或他人的消息。

## 安全与任务语义

- 原知识问答和真人聊天保持原逻辑；新增任务不是审批、公开资料或对外代发功能。
- 两端都检查实名成员、稳定账号、成员版本和保密协议。任务执行、结果保存、飞书每次发送前重新检查。
- 不把用户材料里的指令当作执行授权；模型只能生成正文，没有脚本、数据库、审批、公开或外发工具。
- 复用 OA → Chat 的签名服务绑定和已配置百炼模型；任务入口不通过公共 Chat API，也不回退到其他模型供应商。
- 明确区分 queued / running / succeeded / failed / cancelled。成果持久化成功后才显示完成。
- 幂等提交、原子执行租约、每人每日100个任务、同时5个未完成任务；每个任务最多执行3次。
- 中断任务标为失败，不能自动重复付费生成；取消后到达的迟到结果不能写入。
- 飞书事件校验加密、Verification Token、请求签名、时间戳、应用和租户；按 message_id 去重。
- 飞书结果分段、每段稳定 UUID。失去发送回执时只在去重窗口内重试，超过50分钟标记 needs_review。
- 不记录模型异常正文、源材料、签名或密钥到日志。材料只在私有任务表保存，不入公开知识库。

## 启用前的发布顺序（本次代码提交不等于生产启用）

1. 审核并合并 PR；备份目标 OA D1 数据库。不得操作网站 D1。
2. 对已核验的 OA D1 应用 `migrations/oa/0002_ai_workbench.sql`。
   这是独立扩展迁移，与已有飞书通知扩展相同，不属于 drizzle 的0033知识库迁移序列。
   不修改已部署的迁移编号，不运行删除或清空命令。开启前检查两个新表与索引符合该 SQL。
3. 发布 Chat Worker 的**私有任务桥接操作**，再发布 OA Worker。
   公共 Chat 的页面、普通问答和知识检索未修改；仅发布 OA 而不发布这段桥接代码，任务不能生成。
4. OA Worker 设置 `OA_AI_TASKS_ENABLED=true`。默认关闭；未配置不会接收或执行任务。
   继续使用既有 `CHAT_SERVICE` 和 `PUBLIC_LAB_AI_SERVICE_TOKEN`，不要求把百炼密钥复制到 OA。
5. 检查 OA 现有 Cron 已启用，建议每分钟一次，用于离开页面后的队列处理和飞书结果回传。
   OA 页面提交后会主动启动执行；关闭页面后是否继续取决于 Worker/Cron 是否正常。
6. 先用一份合成材料在 OA 做真实验收：创建→生成→刷新后成果仍在→Word下载可打开。
   此项必须在发布授权后使用真实成员会话验证，不能用单元测试冒充真实百炼联调。

## 飞书管理员必须完成的配置

沿用 OA 飞书登录同一自建应用，否则现有稳定 open_id 绑定不能自动复用。
启用机器人，授予“读取用户发给机器人的单聊消息”和“以应用身份发送消息”等最小权限，
配置 `im.message.receive_v1` HTTP 事件订阅并发布企业应用版本。
回调地址：`https://oa.omindos.ai/api/integrations/feishu/ai-events`。
具体权限名以飞书管理后台显示为准，不申请全员聊天记录读取权限。

在 OA Worker 的服务器端 Secrets 中配置：
`FEISHU_AI_ENCRYPT_KEY`、`FEISHU_AI_VERIFICATION_TOKEN`。
已有 `FEISHU_LOGIN_APP_ID`、`FEISHU_LOGIN_APP_SECRET`、`FEISHU_LOGIN_TENANT_KEY` 继续复用。
上述配置完成后设置 `FEISHU_AI_TASKS_ENABLED=true`；不得把密钥放到浏览器、GitHub文件、PR或聊天正文。
URL验证事件需要加密且Token匹配，普通事件还必须有有效请求签名。
成员先在 OA 完成飞书账号绑定和保密签署，再进行机器人私聊真实联调。

## 数据维护和回滚

关闭 `OA_AI_TASKS_ENABLED` / `FEISHU_AI_TASKS_ENABLED` 即停止新任务/机器人任务处理，
不删除任务表或已有成果。部署回退也不执行 DROP TABLE。
任务表包含用户提交的材料，按私有研发资料保管。删除策略应另行确认后实现，不能擅自清空历史。
现有自定义 OA 迁移导出不包含这两张独立扩展表；迁移整个 OA 时需额外通过 D1 原生备份/导出保留，
在补齐自定义迁移支持之前不得把其导出包当作完整 AI 工作台备份。
