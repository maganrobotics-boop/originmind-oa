# 机器人学习闯关系统：新手村

## 一、定位

“新手村”是面向 ARTS Robotics、IUS 智能无人系统校队、源灵具身智能产业协会及 OriginMind 联合项目的新生训练与项目准入系统。

它不是传统课程平台，而是一个“学习任务 + 知识问答 + AI 助教 + OA 审核 + 项目分流”的闭环系统。

核心目标：

- 让学生像打游戏一样完成机器人基础训练；
- 让老师快速判断学生是否具备进入项目组的能力；
- 让优秀提交、常见问题和项目经验沉淀进实验室知识库；
- 把招新、培养、分流、项目准入和知识沉淀连成一条线。

## 二、整体结构

系统由四层组成：

| 层级 | 作用 |
| --- | --- |
| 新手村任务系统 | 管任务、等级、积分、徽章、路线、提交记录 |
| 知识问答 | 学生随时提问，如 ROS2 安装、报错、代码问题 |
| 实验室大模型 | 结合知识库、任务上下文、学生画像进行答疑、点评和推荐 |
| OA 后台 | 审核提交、归档优秀成果、管理权限和知识库 |

基本流程：

```text
学生登录
填写基础情况
进入新手村地图
完成任务并提交证据包
AI 自动初评
助教/老师审核
通过后获得 XP、徽章或通行证
优秀提交进入 OA 待审
审核后沉淀到知识库
系统推荐项目组或下一阶段任务
```

## 三、MVP 阶段：第一版做什么

MVP 是最小可用版本，不追求完整仿真和真机自动评测，而是先完成最小闭环。

第一版应包含：

| 模块 | MVP 功能 |
| --- | --- |
| 登录 | 校内邮箱登录或游客体验 |
| 新手测评 | 询问年级、专业、编程基础、ROS2 基础、兴趣方向 |
| 任务地图 | 显示 Lv.1 到 Lv.3 的基础任务 |
| 任务详情 | 展示目标、步骤、提交材料、通过标准 |
| 作业提交 | 支持截图、日志、代码链接、文字说明 |
| AI 点评 | 自动给完成度、问题、补充建议 |
| 人工审核 | 助教/老师选择通过、退回、优秀 |
| 积分等级 | 完成任务获得 XP、徽章、等级 |
| 后台 | 老师查看学生进度、待审核提交和卡关情况 |

第一批任务控制在 10–15 个：

- 工具安装 3 个；
- Linux/Git 3 个；
- Python/C++ 2 个；
- ROS2 3 个；
- 仿真导航 2 个；
- 出村考核 1 个。

MVP 验证三件事：

- 学生愿不愿意用；
- 任务设计是否清楚；
- 老师能否通过系统发现靠谱学生。

## 四、学生端界面

学生端不应做成传统课程平台，而应做成“游戏地图 + 任务大厅 + AI 导师”。

第一屏要回答三件事：

- 我现在在哪一级；
- 下一关要做什么；
- 卡住了问谁。

### 1. 新手村首页

首页建议采用 2D 节点地图：

```text
入村登记 -> 装备铺 -> 训练场 -> ROS2 仿真场 -> 任务大厅 -> 出村考核 -> 项目组入口
```

每个节点显示状态：

- 未解锁；
- 进行中；
- 待审核；
- 已通过；
- 优秀。

顶部显示：

- 学生等级；
- XP；
- 当前路线；
- 已获得通行证；
- 下一关入口。

### 2. 任务详情页

每一关一页，避免长篇课程文档。

页面结构：

- 任务名称；
- 目标一句话；
- 预计耗时；
- 前置条件；
- 步骤提示；
- 需要提交什么；
- 通过标准；
- 常见问题；
- 上传/提交按钮；
- 问 AI 导师。

示例：

```text
任务：运行第一个 ROS2 节点
目标：成功启动 turtlesim，并查看 topic 列表
提交：终端截图 + ros2 topic list 输出 + 100 字说明
通过标准：能看到 /turtle1/pose 和 /turtle1/cmd_vel
```

### 3. AI 导师

AI 导师应常驻在任务页右侧或作为浮动入口。

常用按钮：

- 问导师；
- 解释报错；
- 检查我的提交；
- 给我下一步；
- 生成复盘草稿。

AI 导师应自动知道：

- 学生当前任务；
- 学生基础水平；
- 已提交内容；
- 是否被退回；
- 相关知识库资料。

### 4. 个人主页

个人主页展示成长档案：

- 等级；
- XP；
- 徽章；
- 通行证；
- 已完成任务；
- 当前路线；
- 能力雷达图；
- 提交记录；
- 老师点评；
- 推荐项目组。

## 五、老师/助教后台

老师端不要过度游戏化，应偏 OA 风格，强调效率。

核心页面：

- 待审核提交；
- 学生进度；
- 卡关学生；
- 优秀提交；
- 任务完成率；
- 路线分布；
- 项目准入名单。

审核页面展示：

- 学生提交内容；
- 截图、日志、代码链接、说明；
- AI 初评；
- 历史提交；
- 通过标准；
- 审核按钮：通过、退回、优秀、归档知识库。

## 六、通行证机制

通行证是“权限 + 能力证明”，不是装饰徽章。

通行证决定学生能进入什么任务、项目和权限范围。

| 通行证 | 拿到后能做什么 |
| --- | --- |
| 新手村通行证 | 可以正式提交任务，不再只是游客体验 |
| 工具通行证 | 证明会用 Linux、Git、VS Code，可接基础开发任务 |
| ROS2 通行证 | 可以进入 ROS2 仿真任务和更深教程 |
| 仿真导航通行证 | 可以做 SLAM/Nav2 相关任务 |
| 真机安全通行证 | 可以预约真实机器人、进入真机训练 |
| 项目成员通行证 | 可以申请加入四足组、感知组、导航组等真实项目 |
| 助教通行证 | 可以审核低级任务、点评新同学提交 |
| 知识库贡献通行证 | 可以提交 FAQ/经验贴进入 OA 待审 |

通行证逻辑：

```text
学习成果 -> 权限解锁 -> 项目准入
```

示例：

```text
想进四足组：
需要 ROS2 通行证 + 控制基础通行证 + 真机安全通行证

想进源灵产业协会：
需要项目交付通行证 + 文档通行证

想当助教：
需要完成新手村 + 多次优秀提交 + 老师确认
```

## 七、任务证据包

每个任务提交不应只是一句“我完成了”，而应是一个可追溯的证据包。

证据包包括：

- 运行截图；
- 终端日志；
- 代码链接；
- 实验说明；
- 问题复盘；
- AI 初评；
- 助教评语；
- 最终状态。

价值：

- 老师能查；
- 学生能复盘；
- AI 能学习；
- OA 能归档；
- 项目能选人。

## 八、大模型能做什么

大模型适合做“助教”和“评审助手”，但不应在第一版完全替代老师/助教。

| 功能 | 大模型能力 | 说明 |
| --- | --- | --- |
| 知识问答 | 可以 | 基于实验室知识库、课程资料、ROS2 文档回答 |
| 当前任务辅导 | 可以 | 知道学生正在做哪一关，回答更有针对性 |
| 报错解释 | 可以 | 学生上传日志后解释错误原因和排查步骤 |
| 作业初评 | 可以 | 看截图、日志、README、代码链接，给完成度和建议 |
| 学习路线推荐 | 可以 | 根据学生基础和完成情况推荐下一关 |
| 自动生成任务说明 | 可以 | 老师给主题，AI 生成任务要求和评分标准 |
| 自动沉淀 FAQ | 可以 | 将高频问题整理成知识库草稿 |
| 最终通过/不通过 | 半自动 | AI 初评，助教/老师最终确认 |
| 真机器人任务验收 | 半自动 | AI 可看日志、视频和报告，关键验收人工把关 |

合理模式：

```text
大模型初评 + 系统自动检查 + 助教最终确认
```

不能过度依赖大模型的部分：

- 代码是否真的能跑；
- 机器人是否真的完成任务；
- 实验数据是否真实；
- 学生是否复制粘贴别人结果；
- 安全相关操作是否合规。

## 九、路线分流

出村后必须有明确出口，否则学生通关后会流失。

建议出口：

- IUS 智能无人系统校队；
- 源灵具身智能产业协会；
- 四足巡检项目；
- 感知组；
- 导航/SLAM 组；
- 控制组；
- 机械设计组；
- AI OS / Agent 组；
- 助教；
- 知识库贡献者。

系统应根据学生任务表现推荐：

- 更适合哪个方向；
- 还缺哪张通行证；
- 是否可以申请项目组；
- 是否建议先补基础任务。

## 十、需要提前考虑的问题

### 1. 任务标准

每一关都要定义：

- 目标；
- 前置任务；
- 预计耗时；
- 提交材料；
- 通过标准；
- 常见错误；
- 是否允许 AI 初评；
- 是否必须人工审核。

### 2. 任务版本化

任务会随着 Ubuntu、ROS2、工具链变化而更新。

系统要记录：

- 学生完成的是哪一版任务；
- 任务修改历史；
- 旧版本是否还有效；
- 标准答案和审核标准是否同步更新。

### 3. 能力标签

每个任务应标注能力标签：

- Linux；
- Git；
- Python；
- C++；
- ROS2；
- SLAM；
- Nav2；
- 感知；
- 控制；
- 机械设计；
- 文档表达；
- 项目交付。

能力标签用于生成学生能力画像。

### 4. 失败记录

失败、退回、补交、卡关次数都应记录。

这些数据可以判断：

- 学生是否认真复盘；
- 哪些任务说明不清；
- 哪些知识点最容易卡；
- 哪些学生需要助教主动帮助。

### 5. 防作弊

不能只靠截图。

逐步加入：

- 命令输出；
- 日志；
- GitHub 链接；
- 运行视频；
- 代码提交记录；
- 口头答辩；
- 助教抽查。

### 6. 真机安全

真实机器人任务应单独分级：

- 软件任务；
- 仿真任务；
- 低风险真机任务；
- 高风险真机任务；
- 电池、机械臂、矿区场景等特殊安全任务。

真机任务必须要求：

- 安全培训；
- 真机安全通行证；
- 预约机制；
- 责任记录；
- 人工确认。

### 7. 成本控制

需要限制：

- AI 点评频率；
- 单次日志长度；
- 视频大小；
- 文件存储周期；
- 大模型调用预算。

### 8. 权限回收

学生离队、助教毕业、通行证过期后，应能回收权限。

所有关键操作要留审计记录：

- 谁审核了谁；
- 谁给了通行证；
- 谁归档了知识库；
- 谁开放了真机权限。

## 十一、任务模板

老师创建任务时，不应每次从零写。

建议任务模板字段：

```text
任务名称
适合年级
预计耗时
前置通行证
能力标签
任务目标
操作步骤
提交材料
通过标准
常见错误
参考资料
是否允许 AI 自动初评
是否需要人工审核
是否可归档知识库
```

## 十二、第一版建议范围

第一版建议只做：

```text
登录后进入新手村
游客只能看介绍和体验前 2 个任务
校内邮箱用户可以提交任务
助教/老师可以审核
任务页可问 AI 导师
提交后 AI 自动初评
优秀提交可归档到 OA 草稿
```

第一版不建议做：

- 复杂 3D 地图；
- 完整云端仿真；
- 真机自动验收；
- 大规模视频分析；
- 全自动通过/不通过；
- 复杂排行榜。

## 十三、后续可扩展功能

- 导师 NPC：不同方向配置不同 AI 助教；
- 任务生成器：老师输入目标，AI 生成任务和评分标准；
- 错题本：常见报错自动沉淀；
- 项目试炼：真实项目拆成一组关卡；
- 出村报告：自动生成学生能力报告；
- 设备预约：与真机训练和实验室安全制度结合；
- 团队任务：支持组队、分工、队长和贡献记录；
- 排行榜：更重视进步、复盘、助人、稳定交付，而不是只比速度；
- 数据导出：用于招新复盘、评奖、项目推荐和课程总结。

## 十四、核心判断

新手村不是终点。

它的本质是：

```text
筛选 -> 训练 -> 分流 -> 交付 -> 沉淀
```

最终要回答老师最关心的几个问题：

- 谁真的能干活？
- 谁适合哪个方向？
- 谁可以碰真机器人？
- 谁的成果值得进入知识库？
- 谁可以进入真实项目？

第一版只要把数据结构和流程留好，后续可以逐步接入更复杂的仿真、真机任务和项目管理。
