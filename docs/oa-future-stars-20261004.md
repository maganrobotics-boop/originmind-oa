# OA 未来之星（2026-10-04）

OA 已保留现有的工作台、审批、资料库、大模型四项，在最右侧增加第五项“未来之星”。已完成准入的管理员可使用，入口为 https://oa.omindos.cn/#future-stars 。

## 管理内容

- 课程学生进度：搜索学生、筛选课程、查看草稿与提交记录、AI 反馈、新手村进度和免修情况。
- 竞技赛获奖：管理员确认获奖依据后登记，明确绑定已有账户；允许先登记、后绑定。
- 荣誉墙管理：颁发、绑定账户、隐藏、恢复展示、撤销和查看操作记录。竞技赛获奖与荣誉墙使用同一数据源。

OA 根据真实管理员身份生成签名请求，Chat 校验 HMAC、有效期、一次性 nonce 和参数白名单。管理写入校验同源、限制请求体大小和操作频率。公开荣誉不返回邮箱、证明材料或操作记录；隐藏的荣誉保留本人可见，撤销的荣誉停止展示。

## 与当前线上版本的集成

当前阿里云生产版本包含仓库 main 尚未同步的四栏导航、课程系统和 AI 成员功能。因此本分支提供可复用模块及 `scripts/integrate-future-stars.py`，通过明确的源码锚点向当前生产版本应用增量。脚本会拒绝不匹配的锚点，不用 main 覆盖服务器版本。

集成脚本修改当前 OA 的导航和页面挂载、Chat 的现有课程服务和静态路由。旧 `/learning/admin` 和 `/learning/honors/admin` 入口跳转至 OA。现有课程、准入、审批、竞技场身份与 AI 成员实现继续使用当前版本。

部署顺序：

1. 从当前 OA、Chat release 创建独立候选目录，保留运行时依赖的符号链接。
2. 对候选目录运行集成脚本；指定 `--oa-user originmind-oa --chat-user originmind-chat`，为候选代码恢复服务账户所有权。所有权处理不遍历外部符号链接。
3. 在 OA 候选目录完成 Next 生产构建。若以 root 构建，构建后再次恢复候选目录的服务账户所有权。
4. 用两个服务账户及 systemd 的附加组，在临时端口验证启动和接口。使用数据库副本，不在生产中创建测试奖项。
5. 备份 OA、Chat、课程 SQLite；运行 `aliyun/future-stars-migrate.mjs`，将现有私有荣誉登记导入新表，保留原 ID、颁发日期和明确的账户绑定。
6. 原子切换当前 release 链接，依次重启 Chat 和 OA。健康检查地址分别为 `/_health` 和 `/api/session`；异常时切回原链接。

荣誉迁移可重复执行，不重置已有隐藏或撤销状态。回滚应用时保留新增荣誉表，避免删除部署期间产生的记录。

原生产页面默认选中“大模型”，管理页面的“返回 OA”链接访问 `/` 时因此重新显示聊天界面。`scripts/fix-oa-home.py` 将初始视图、初始主导航以及飞书/GitHub 登录成功后的落点改为工作台；“未来之星”的深链接仍可直接打开。集成脚本已包含这一步，不增加栏目。

修复只更改当前生产 `app/page.tsx` 的四处落点及深链接监听。同一页面打开“未来之星”链接或使用浏览器返回时也会同步栏目；初始登录回调的账户绑定与个人资料逻辑不变。重复应用不会重复修改；源码锚点发生变化时会停止。新的 OA release 为 `oa-home-workbench-20261004-v1`，保留 `oa-future-stars-20261004-v1` 作为回滚点，Chat 继续使用原版。

修复版 TypeScript 与 Next 生产构建通过。当前生产页面在桌面 1280 px、手机 390 px 下完成 16 项浏览器检查，覆盖主页、刷新、管理页返回、两种登录回调、同页深链接和从大模型返回工作台；没有站外请求或浏览器错误。浏览器测试模拟登录状态与业务接口，页面和资源来自实际候选 Next 服务。生产切换后已核验域名、服务健康及浏览器主脚本与候选文件完全一致；其他源码和 Chat 当前版本未变。
