- 已上线 OA 的按钮在 `!ready` 时被 disabled，服务未就绪的错误只在页面上方显示；长材料情况下用户在底部只能看到灰按钮。

## 修改

1. 服务未就绪时按钮改为“检查任务服务（保留材料）”，可以重新查询，不静默失效，也不提交任务或调用模型。原因同时显示在按钮旁。
2. 恢复后同一页面可重新进入执行状态；不会清空输入、重载页面或把未提交材料写到本地存储。错误登录 HTML、空 JSON 不能伪装成就绪。
3. API 区分登录、准入、关闭开关和任务库不可用。工作台已启用时必须同时验证任务表、文件归档表可读才返回任务列表。
4. 既有 deploy-oa.yml 新增 `enable_ai_workbench` 布尔选项，默认 false。仅受保护的 main 手动发布、完整测试和普通 OA 正式发布成功后才执行初始化并启用步骤。
5. 启用步骤复核同一运行的不可变构建校验和、实际 Worker/D1/官网库隔离、既有版本与确认串、冻结状态，记录整个 OA D1 的 Time Travel 恢复书签。只执行既有两份可重复 CREATE DDL；不修改历史 SQL，不删除资料或迁移台账，也不连接飞书。
6. 原有同名结构不匹配、未知任务结构或初始化不完整时停止。结构完整校验后才使用显式变量部署同一构建并回读 OA_AI_TASKS_ENABLED=true；保留其他远端变量。Cloudflare 原始元数据只在临时私有目录处理，不输出密钥。

## 启动

在现有 OA 正式发布入口选择 main，保留环境确认串，并勾选“初始化并启用 AI 工作台”。无需重新发布 Chat。
一次发布依次完成普通 OA 部署、恢复点、任务表初始化、启用和只读验证。
默认不勾选时不改变任务功能开关；后续普通部署继续保留远端变量。
无需新增付款方式、调整预算或新增 Secrets。失败不能宣称工作台已可用。
